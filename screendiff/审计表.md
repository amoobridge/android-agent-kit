# screendiff · 审计表

**License**：Apache-2.0 · **版本**：0.1.0 · **日期**：2026-10-27

---

## 一、这是什么

GUI Agent 的**界面变化语义层**。两个界面快照进，回答三个问题：
界面变了没有、变了什么、我的动作起作用了吗。

**不涉及**：设备控制、权限申请、进程注入、任何第三方应用的针对性处理。
纯算法库，输入是结构化元素列表，输出是结构化变化集。

## 二、为什么有意义（缺口论证）

安卓侧所有 agent 项目都各自写 ad-hoc 的界面比对，且主流做法是
**按位置逐位比对**。这在上滑场景下把「平移」误报成「所有元素变化」，
在顶部插入场景下把真正的新元素淹没在噪声里。

我们没找到任何独立、可复用、有规范的安卓界面变化语义层。
`a11y-computer-use`（Apache-2.0）有元素引用但**不支持安卓**且是 MCP 形态。

## 三、命名与框架纪律自查

| 检查项 | 结论 |
|---|---|
| 不点名任何第三方应用 | ✅ 全文无应用名；真实 dump 来自系统设置（AOSP），非第三方 |
| 以「用户不方便时的场景化辅助」为框架 | ✅ 定位为 agent 决策的支撑层，不涉及代操作 |
| 走系统公开能力 | ✅ 输入是 a11y 树投影（uidref 产出），本库不接触设备 |
| 技术无害 | ✅ 纯计算，无网络、无文件写、无子进程（测试除外） |
| 增益生态 | ✅ 规范 + 双语言参考实现 + 黄金向量 + 语言无关验证工具 |

## 四、审计表（按能力列）

| 能力 | 输入 | 输出 | 依赖 | 权限 | 用户同意点 | 撤销路径 |
|---|---|---|---|---|---|---|
| `diff(prev, cur)` | 两个元素列表 | ChangeSet | 无 | 无 | 不适用 | 不适用 |
| `effect_of(cs, ref)` | ChangeSet + ref | Effect | 无 | 无 | 不适用 | 不适用 |
| `is_stuck(hist, n)` | ChangeSet 列表 | bool | 无 | 无 | 不适用 | 不适用 |
| `is_loading(cur)` | 元素列表 | bool | 无 | 无 | 不适用 | 不适用 |

**本库不申请任何权限、不访问任何设备、不发起任何网络请求。**

## 五、测试证据

| 层 | 结果 |
|---|---|
| pytest | **33 passed** |
| 黄金向量 | 6 文件 27 用例，Python 27/27 · JS 27/27 |
| 跨语言随机差分 | 120 组，**0 分歧** |
| 真实 dump 比对 | 3 对，**完全一致** |
| 工具反向验证 | 4 种破坏形态**全部检出** |

真实设备指标（Android 15 AVD，系统设置）：

| 场景 | 指标 |
|---|---|
| 列表上滑 | 平移识别 9/11，误报（added+removed+state+label）= **0** |
| 单元素状态变化 | 精确 1 label + 1 state，其余 **0** 误报 |
| 连续无变化 | `is_stuck(n=3)` 正确返回 `True` |

## 六、已知风险与缓解

| 风险 | 缓解 |
|---|---|
| 跨屏比对产生 added/removed 噪声 | SPEC §9.1 明确要求调用方前置过滤；README 边界清单第 1 条 |
| 全屏容器误匹配小元素 | 面积比闸门（SPEC §4.1）+ 回归测试 |
| 空 class_name 误判同类 | 三个身份 tier 强制非空 + 回归测试 |
| 贪心匹配非最优 | SPEC §4.3 明确选可判定性；已知边界第 5 条 |
| `is_loading` 准确性 | 定为应该级，实现可调但不得声称符合 |
| 真实样本仅 4 个 dump | README 边界清单第 7 条明示为方向性指标 |

## 七、适用范围

整个 `screendiff/` 目录。

理由：纯算法库、Apache-2.0、零依赖、命名中性、不触碰任何第三方应用，
且方法论（跨语言独立实现 + 变异敏感性元测试）对生态有增益。
