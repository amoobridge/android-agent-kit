# claimcheck 规范 · 经验性声明的验证等级

**版本** 0.1.0 · **日期** 2026-10-27 · **License** Apache-2.0

---

## 0. 这个库是什么

它回答一个问题：**一条「实测发现」到底被验证到什么程度？**

起因是 2026-10-27 这一天，我在同一个项目里**四次把未复现的观测写成了结论**：

| # | 声明 | 当时的证据 | 复现检查结果 |
|---|---|---|---|
| 1 | `adb shell` 把 LF 转 CRLF 污染 XML | **无**（凭经验写入） | 两种读法字节完全相同；XML 单行 0 换行，现象无从显现 |
| 2 | `am start`+`BACK` 不能复位滚动位置 | 一次观测 | HOME 键可复位；结论方向对但**机制归因错误** |
| 3 | 「200ms 以下手势完全无效」 | 一次观测 | 复位用错导致的**阈值假象** |
| 4 | 「`am start` 是恢复原语」 | 一次观测 | 换起始状态后**不成立** |

四条的共同点：**单次观测 + 漂亮的规律**。
这比一条丑陋的观测更危险——因为它会被直接写进文档、被引用、被当作设计依据。

> **单次观测只能产生假设，不能产生结论。**

---

## 1. 验证等级

| 级 | 名称 | 判据 |
|---|---|---|
| **V0** | 假设 | 单次观测（`observations <= 1`） |
| **V1** | 可重复 | 同一起始状态复现 ≥ 3 次 |
| **V2** | 跨状态 | ≥ 2 个不同起始状态各复现 |
| **V3** | 交叉验证 | ≥ 2 个独立通道/方法 |
| **V4** | **已推翻** | 复现检查不成立 |

`MIN_LEVEL_FOR_SPEC = V1`：低于 V1 不得写进 SPEC 正文作结论。

---

## 2. 分级判定

```python
classify(observations, distinct_states, independent_channels) -> Level
```

**三个参数必须分别计量，不能合并成一个"测试次数"。**

★ 复现 10 次但同一起始状态 → 仍是 **V1**，不是 V2。
★ 有独立通道时优先判 V3，即使只有一个起始状态。

---

## 3. 危险信号

```python
danger_signals(observations, has_control, has_baseline) -> list[str]
```

| 信号 | 含义 |
|---|---|
| `single-observation` | 只有一次观测 |
| `no-negative-control` | 没有对照组 |
| `no-baseline` | 没有基线 |

```python
should_verify_before_writing(observations, has_control, has_baseline) -> bool
```

**★ 单次观测本身就足够触发，不需要凑够两个信号。**

第一版写成 `>= 2` 个信号，结果今天第 4 条（有对照组、单次观测）
**逃逸了**——而那正是今天最像发现的一条。

---

## 4. 推翻 ≠ 删除

```python
refute(claim, refuted_by) -> Claim
```

推翻一条声明时：**改级为 V4、记录 `refuted_by`、保留原始观测**。

不是从文档里删掉。理由：

1. **删掉之后没人知道这里有过一个结论**，下一个人会重新发现它
2. `original_observation` + `refuted_by` 本身就是最有价值的教学材料
3. 今天四条里，第 2 条（`reset_home`）的机制归因错误**正是在留档之后**才被看清的

`citable` 对 V4 返回 False——**即使它有 10 次观测**。

---

## 5. 文档标注

```python
required_marker(claim) -> str | None
```

| 级 | 必须出现的标注 |
|---|---|
| V0 | `未复现` |
| V1 / V2 / V3 | 无 |
| V4 | `已推翻，不得作为结论` |

---

## 6. 复现检查的最小协议

1. 记录当时的**完整起始状态**（不只是命令）
2. 从同一状态重跑 ≥ 3 次
3. 换一个不同的起始状态重跑，≥ 2 个状态
4. 若可能，用另一条通道交叉验证（截图 / `dumpsys` / 别的工具）
5. 有一条不成立 → 改级 V4 并留档，**不是删除**

---

## 7. 一致性条件

| # | 条件 |
|---|---|
| C1 | 分级判定 必须 分别计量观测数、状态数、通道数 |
| C2 | `should_verify_before_writing` 必须 在单次观测时返回 True |
| C3 | `refute` 必须 保留 `original_observation`，不得 删除 |
| C4 | V4 的 `citable` 必须 为 False，不论观测数多少 |
| C5 | `required_marker` 必须 对 V0 返回「未复现」、V4 返回「已推翻」 |

---

## 8. 边界

1. **这是过程规范，不是测量工具。** 它不定"几次算够"，只定"不够时该怎么办"。
2. **不覆盖统计显著性**——本项目的观测是确定性的界面行为，不是抽样。
3. **不覆盖"观测本身是否可信"**——那是 capturetrap 的管界（观测装置会静默失效）。
4. **今天的四条案例是实例，不是边界**：换设备/换 App 会产生新的形态。

## 9. 与其他库的关系

| 库 | 关系 |
|---|---|
| `capturetrap` | claimcheck 假设观测可信；capturetrap 保证观测**装置**可信 |
