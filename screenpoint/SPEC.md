## 1. 问题陈述

GUI Agent 的标准回路：

```
① 截图          设备像素，如 1080x2400
② 缩放          为省 token 压到 756x1680
③ 送模型        模型看到的是 756x1680
④ 模型指个点    模型返回的是 756x1680 坐标系下的点
⑤ 反算回设备    乘回去
⑥ 点击          adb input tap / dispatchGesture
```

⑤ 是**整条链上唯一的确定性环节，却常被交给模型**。典型做法是往
prompt 里塞一句 "multiply its x by 1.5 and y by 1.5"。后果：

- 模型算术不可靠，误差无界且不可复现
- ratio 预先四舍五入到 3 位小数，1080px 宽屏上单轴误差可超 0.5px
- 宽高比不一致时无偏移补偿，系统性偏航
- 归一化网格（0-1000 / 0-1）无定义反算
- 中间步骤取整，误差链式累积

**本规范的唯一主张：⑤ 必须由确定性代码完成。**

## 2. 坐标空间

### 2.1 定义

**坐标空间**是一个具名的、带尺寸的二维平面，记作 `(name, size, kind)`。

- `size`：`(width, height)`，正整数，单位像素
- `kind`：
  - `pixel` —— 值即像素坐标，原点左上，`x ∈ [0, width]`，`y ∈ [0, height]`
  - `normalized` —— 值即归一化网格坐标，`x,y ∈ [0, grid_n]`，`grid_n` 通常为
    1000（UI-TARS 风格）或 1（小数风格）

**必须**：任何坐标在传递前必须绑定到一个具名空间。未绑定空间的坐标
不得被用于点击。

### 2.2 为什么 normalized 也要带 size

归一化空间仍然绑定真实屏幕尺寸，因为模型常在**同一张归一化截图**上工作，
而截图本身是缩放过的。`size` 记录的是该空间对应的**真实屏幕像素**，
`grid_n` 记录模型使用的数值上界。两者缺一不可。

## 3. 缩放模式

截图相对屏幕的缩放方式必须显式声明，取值 `stretch` / `fit` / `crop`。

设 `src` 为截图空间，`dst` 为目标空间，`s` 为缩放系数，`o` 为偏移：

| 模式 | `s` | `o` | 说明 |
|---|---|---|---|
| `stretch` | `sx = dst.w/src.w`，`sy = dst.h/src.h` | `(0, 0)` | 各轴独立，宽高比失真 |
| `fit` | `s = min(dst.w/src.w, dst.h/src.h)` | `((dst.w − src.w·s)/2, (dst.h − src.h·s)/2)` | 完整装入，留白居中 |
| `crop` | `s = max(dst.w/src.w, dst.h/src.h)` | 同上 | 完全覆盖，超出裁掉 |

映射公式（`fit` 与 `crop` 同式，仅 `s` 取法不同）：

```
dst_x = src_x · s + o_x
dst_y = src_y · s + o_y
```

**必须**：调用方必须知道截图是怎么产生的，并如实声明。猜一个模式
比抛错更危险——猜错时错误是静默的。

**应该**：默认 `stretch`，因为它是当前业界最常用的做法（直接 resize）。

## 4. 映射规则

### 4.1 归一化 → 像素

```
px = v / grid_n · width
py = v / grid_n · height
```

**不得** 写成 `v / width · grid_n` 之外的任何变体；特别地，
`v / grid_n · (width − 1)` 是**另一种约定**，本规范不采用，采用者
必须在自有文档中明示。

### 4.2 浮点优先

映射全程必须保持浮点。**不得** 在中间步骤取整。

理由：一次 `int()` 截断在 1080px 上最多丢 1px；链式两步就是 2px；
叠加 letterbox 偏移后误差与目标尺寸同阶。

### 4.3 取整规则（唯一）

仅在最终产出可点击像素时取整，规则为 **half-up**：

```
round(v) = floor(v + 0.5)
```

**不得** 使用 banker's rounding（`round-half-even`）。Python 内建
`round()` 与 NumPy `rint` 均为 banker's rounding，**不可直接用**。

### 4.4 钳制与上报

越界点必须钳制到 `[0, width−1] × [0, height−1]`，且必须返回一个
`clamped` 标记。

**不得** 静默钳制。钳制发生意味着模型的输出不可信，调用方需要知道。

### 4.5 矩形映射

矩形必须用**对角点变换**后重算宽高，不可直接缩放宽高：

```
tl' = map(x, y)
br' = map(x + w, y + h)
rect' = (tl'.x, tl'.y, br'.x − tl'.x, br'.y − tl'.y)
```

理由：`fit`/`crop` 下两轴系数不同，直接缩放宽高会破坏几何一致性。

## 5. 对实现的要求

一个一致实现必须提供：

| 函数 | 输入 | 输出 |
|---|---|---|
| `map_point` | `(x, y, src, dst, fit)` | `[x, y]` 浮点 |
| `map_rect` | `(x, y, w, h, src, dst, fit)` | `[x, y, w, h]` 浮点 |
| `to_device_pixel` | `(x, y, src, dst, fit)` | `[x, y, clamped]` 整数 + 标记 |

`fit` 必须为必填参数，不提供默认值——迫使调用方显式思考。

实现不得在内部缓存或复用跨调用的取整结果。

## 6. 一致性测试

`vectors/*.json` 为黄金向量。任何语言实现跑通全部向量即视为一致。

向量文件形状：

```json
{
  "id": "fit-pillarbox-001",
  "title": "Pillarbox：宽屏内容塞进窄屏，左右留白",
  "why": "模型看到的内容居中、两侧有黑边。按比例硬乘会整体右偏。",
  "src": { "kind": "pixel", "width": 1080, "height": 1920 },
  "dst": { "kind": "pixel", "width": 1080, "height": 2400 },
  "fit": "fit",
  "cases": [ { "in": [0, 0], "out": [0.0, 240.0] } ]
}
```

浮点比较容差 `1e-9`（绝对）。

新增向量必须同时提供 `why` 字段，说明这个用例防的是什么 bug。
没有 `why` 的向量不允许合并——它会被后来人当成无意义数据删掉。

## 7. 已知不在本规范范围内

以下问题真实存在，但 v0.1 不覆盖，列出来避免误解：

- **显示挖孔 / 圆角**：截图通常不含状态栏挖孔区，但 `wm size` 报告的是
  完整屏幕。两者差一个状态栏高度，需调用方自行处理。
- **多窗口 / 分屏**：坐标空间随前台窗口变化，本规范假定单一全屏空间。
- **RTL 镜像**：`layoutDirection` 为 RTL 时截图已镜像，坐标无需额外处理，
  但元素语义可能相反。
- **旋转**：旋转会交换宽高，本规范要求调用方在旋转后重建空间。
- **`fit` 模式未知**：若截图管线不可控，无法可靠反算。此时应该
  直接请求未缩放截图，而非猜测。

### 7.6 重采样相位（真机验证中发现，重点）

降采样是**多对一**：输出第 `i` 个像素对应源图的一片区域，不是一个点。
不同重采样核在这片区域里挑的代表不同：

| 做法 | 输出 `i` 取的源像素 |
|---|---|
| PIL `resize(..., Image.NEAREST)` | `floor((i + 0.5) · s)` |
| 步长抽样 `arr[::k, ::k]` | `i · k` |
| 本规范的反算 | `floor(i · s + 0.5)` |

三者最多相差 1px。**这是相位约定差异，不是映射错误。**

推论，对实现者：

1. 不要用「反算结果是否等于某个特定重采样器的取样点」作为正确性判据——
   在图像边缘上必然差 1px，会误报。
2. 正确的判据是「反算结果是否落在输出像素 `i` 对应的源区域内」。
3. 若要求精确复现，**自己控制降采样**（如步长抽样），别用黑盒 resize。
4. 反算只应作为**点击目标**使用，不应作为「取该像素颜色」的依据。

本条由 AVD 真机验证发现：用 PIL NEAREST 做像素级取证时，
648,000 个像素中有 17,353 个（2.7%）颜色不符，且全部集中在梯度边缘。
改用相位明确的步长抽样后 648,000 个像素全数精确命中。

## 8. 参考实现

`screenpoint/` 为 Python 参考实现，Apache-2.0。

```python
from screenpoint import CoordinateSpace, FitMode, Point, to_device_pixel

shot = CoordinateSpace.pixel("model_view", 756, 1680)
dev  = CoordinateSpace.pixel("device", 1080, 2400)

r = to_device_pixel(Point(400, 900), shot, dev, fit=FitMode.STRETCH)
# r.x, r.y, r.clamped
```
