## 1. 问题陈述

GUI Agent 让模型"点一下那个按钮"。模型回来说不清是什么：

```
{"x": 400, "y": 900}                        (规范形状)
(400, 900)                                  (括号)
x=400, y=900                                (键值对)
I'll tap at (400, 900) now.                 (带废话)
```json
{"x": 400, "y": 900}
```                                        (markdown 包裹)
{"x": null, "y": null, "reason": "..."}     (拒答)
[100, 200, 300, 400]                        (bbox，不是 point)
1,400, 900                                  (千分位歧义)
First tap (100, 200), then tap (300, 400).  (两个点)
```

每个项目自己写正则去啃。每段都有 bug，且**bug 都是静默的**——
解析出一个看起来完全正常的 `(1, 400)`，然后点错地方，无人察觉。

## 2. 核心原则

### 2.1 拒答不是异常

模型说"看不到目标"是**正常输出**。实现必须以可区分的失败类型报告它
（本规范用 `NoPointFound`），调用方必须能优雅处理。

**不得** 把拒答退化成默认坐标、上一个坐标、屏幕中心、或随机点。
这类退化比崩溃危险得多——它让 agent 在错误的地方持续行动。

### 2.2 歧义必须上报

当输出无法唯一确定一个点时，实现必须报歧义（`Ambiguity`），
**不得** 替调用方选一个。

典型歧义源：

| 输入 | 为什么不能选 |
|---|---|
| 文本里两个不同位置 | "指哪个"是语义决策 |
| `[x1,y1,x2,y2]` 四元组 | 是 bbox；取哪个角是语义决策 |
| `{"bbox": [...]}` | 同上 |
| `1,400, 900` | 可能是 `(1400, 900)`，也可能是 `(1, 400)` 加游离数字 |
| 像素/归一化两种解释都成立 | 见 §3 |

### 2.3 空间只给线索，不下结论

数值形态常常无法唯一决定坐标系。`(300, 400)` 在 500x500 的图上是像素，
在 1080x2400 的图上是 0-1000 归一化网格——**同一个数值，两种解释都合法**。

实现必须只返回线索枚举，**不得** 返回概率或置信度。

理由：概率会诱使调用方设阈值，而阈值一旦存在就会被绕过。
枚举迫使调用方结合自己声明的空间做显式校验。

### 2.4 格式名必须可移植

格式名必须只依赖**JSON 可序列化**能区分的特征。

因此 `list` 与 `tuple` 不得作为不同格式名——JSON 和多数语言
分不出来，这个区别会让黄金向量不可移植。统一称 `sequence`。

## 3. 空间线索规则

`infer_space(x, y, width, height)` 按序判定，先命中先返回：

| 序 | 条件 | 线索 |
|---|---|---|
| 1 | 两个都是 `[0,1]` 内小数，且不同时为 `{0,1}` 整数 | `NORMALIZED_UNIT` |
| 2 | 两个都是整数，且都在 `[0,width]×[0,height]` 内 | `PIXEL_INT` |
| 3 | 两个都是整数，且都在 `[0,1000]` 内 | `NORMALIZED_1000` |
| 4 | 其他 | `UNKNOWN` |

规则 1 排除 `(0,0)` / `(1,1)` 是故意的：这两个值在两种解释下都合法，
给强线索等于撒谎。

调用方必须结合自己声明的空间校验线索，**不得** 直接用线索决定换算。

---

## 4. 解析顺序

实现应该按以下顺序尝试，先命中先返回：

1. **JSON**（含被 markdown / 废话 / 单引号 / 尾随逗号包裹的）
2. **键值对** `x=.., y=..`
3. **括号数对** `(x, y)` / `<x y>`
4. **裸数对** `x, y` / `x y`

在任何一步之前，必须先检查**千分位歧义**：文本里出现连续 3 个以上
逗号分隔的数字时，必须直接报 `Ambiguity`，不进入后续步骤。

---

## 5. 对实现的要求

一致实现必须提供：

```
parse_point(raw) -> ParsedPoint | raises NoPointFound | raises Ambiguity
```

`ParsedPoint` 必须至少包含：

| 字段 | 用途 |
|---|---|
| `x`, `y` | 数值（可能是像素也可能是归一化） |
| `space_hint` | §3 的线索枚举 |
| `source_format` | 命中的格式名，用于审计与回归 |
| `raw` | 原始输入，出错时回溯 |

实现不得缓存或复用跨调用的解析结果。

实现不得接受单个标量作为点（`42` 不是点）。

## 6. 一致性测试

`vectors/*.json` 为黄金向量。每个文件形如：

```json
{
  "id": "refusal-001",
  "title": "模型拒答或无法确定",
  "why": "拒答是正常输出。若解析器在这里抛异常或猜一个点，agent 会点在随机位置。",
  "cases": [
    { "in": {"x": null, "y": null}, "out": ["nopoint"] },
    { "in": "(400, 900)", "out": ["ok", 400.0, 900.0, "paren_csv"] }
  ]
}
```

`out` 的三种形态：`["ok", x, y, format]` / `["nopoint"]` / `["ambig"]`。

新增向量必须提供 `why`。没有 `why` 的向量不允许合并。

## 7. 与 screenpoint 的关系

两个库解耦，可独立使用：

| | pointparse | screenpoint |
|---|---|---|
| 管什么 | 模型指了哪 | 代码怎么算 |
| 输入 | 模型原始输出 | 已解析的点 + 空间声明 |
| 输出 | 点 + 线索 | 设备可点击像素 |
| 失败语义 | `NoPointFound` / `Ambiguity` | `MappingError` + `clamped` 标记 |

典型链路：

```python
try:
    p = parse_point(model_output)
except NoPointFound:
    handle_refusal()      # 模型说看不到 —— 正常分支
except Ambiguity:
    handle_ambiguity()    # 多个候选 —— 需要人或上层裁决
else:
    r = to_device_pixel(Point(p.x, p.y), shot, dev, fit=FitMode.STRETCH)
    if r.clamped:
        handle_out_of_range()   # 模型指到图外
    else:
        tap(r.x, r.y)
```

注意：`p.space_hint` 只是线索。传给 `screenpoint` 的空间必须由调用方
根据自己声明的坐标系构造，**不得** 从线索推断。
