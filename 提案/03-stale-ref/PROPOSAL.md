# 提案 03 · uidref 引用失效：从「引用消失」到「引用被重新指派」

**提交对象**：uidref 规范（本套件第三件）
**License**：Apache-2.0 · **日期**：2026-10-27 · **状态**：提案
**证据**：真实 dump 4 组 + AVD 真机闭环 + 回归测试

---

## 1. 一句话

`uidref` 的 `StaleRefError` 只覆盖「引用消失」这一种失效。
在真实设备上还存在第二种、也是更危险的一种：**引用仍在，但指向了别的内容**。
本提案把失效判据从「下标是否越界」升级为「快照是否仍是那一份」。

---

## 2. 问题：真机撞出来的

`agentloop` 对照实验 S3（策略视野慢一拍）中，预期结果是：

> 引用派在解析阶段拒绝过期引用，**0 次点空**；坐标派照样点，产生点空。

实测：**两组都只点了 1 次，而且引用派那一次点错了。**

那一帧上，`e5` 这个下标**仍然合法**，但它从
「Security & privacy」变成了「Connected devices · Bluetooth」。
`resolve("e5")` 正常返回一个 `Element`，点击静默落在错误的行上，
导航到了错误的页面。

```
引用消失        → StaleRefError → 拒绝执行      ✅ 已覆盖
引用被重新指派  → resolve() 成功 → 点错          ❌ 未覆盖
```

**为什么第二种更危险**：它不产生任何异常信号。点空至少会被
`screendiff` 判成 `target_unchanged`；点错会导航到另一个页面，
而 agent 看到的只是一次"成功的点击"。

---

## 3. 根因：ref 是序数，不是标识符

`uidref` 的 `ref` 是**文档序下标**（`e1`、`e2`…）。序数的两个性质：

| 性质 | 后果 |
|---|---|
| 不携带内容信息 | 同一个下标在不同内容下指向不同元素 |
| 内容一变就整体平移 | 顶部插入一行，后面全部错位 |

`snapshot_id` 却是**内容哈希**（`sha256(package\|rotation\|root_xml)[:12]`）。
所以「下标合法」与「语义仍有效」之间没有任何联系——这就是缺口。

---

## 4. 真实 dump 证据

用 `screendiff/dumps/` 里真实 dump 逐 ref 比对（非构造数据，
每个快照 11 个可交互元素，**全量计数不抽样**）：

| 迁移 | snapshot_id 相同 | 重指派 ref 数 | 说明 |
|---|---|---|---|
| `c1 → c2` | 否 | **11 / 11（100%）** | 跨页导航 |
| `c1 → c3` | 否 | **11 / 11（100%）** | 跨页导航 |
| `c1 → d1` | 否 | **11 / 11（100%）** | 跨页导航 |
| `c2 → c3` | 否 | 1 / 11 | 同页标签变化（飞行模式开关） |
| `c2 → d1` | 否 | 1 / 11 | 同页标签变化 |
| `c3 → d1` | 否 | **0 / 11** | 纯滚动，9 个元素平移但标签全同 |

四个读数，各自说明一件事：

1. **跨页导航是 100% 重指派。** 页面一跳，上一页的**每一个** ref 都指向了
   别的内容。这不是边缘情况，是导航后的常态。
2. **同页内容变化也会重指派**（1/11）——即便界面看起来"还是那一页"。
3. **纯滚动不重指派**（0/11），9 个元素平移但标签一个没变。
4. **但所有迁移的 snapshot_id 都变了。**

第 3、4 条合起来是设计的关键约束，见 §5.3 与 §6。

> 顺带记一笔：第一版只数了 `e1..e6`，得出"6/6"，低估了近一半。
> 统计覆盖面本身也要有判据——这是这条提案自己的教训。

## 5. 提案：双闸门解析

### 5.1 API 变更

```python
# 现状（v0.1）
snap.resolve("e5") -> Element
    # 仅在下标越界时抛 StaleRefError

# 提案（v0.2）
snap.resolve(ref, since=None) -> Element
    # 闸门一：下标越界            → StaleRefError(reason="ref_gone")
    # 闸门二：since != 自身 id    → StaleRefError(reason="snapshot_mismatch")
```

`Decision` 增加必填字段 `since`，**由策略在产出决策时一并带上**：

```python
@dataclass
class Decision:
    kind: str                       # tap_ref | tap_xy | swipe | done | fail
    ref: str | None = None
    since: str | None = None        # 该 ref 所属快照的 id；tap_ref 时必填
    ...
```

执行侧无法忘记校验，因为 `since` 就在决策对象里，不给就构不成合法的 `tap_ref`。

### 5.2 为什么不会误拒

`snapshot_id` 是内容哈希 ⇒ **内容没变，id 就不变，引用继续有效**。

```
界面未变  → id 相同 → resolve(ref, since=id) 成功   无需重新 dump
界面变了  → id 不同 → 拒绝                         必须重新观察
```

这正是想要的行为：**没有变化就不打扰，一旦变化就强制重新观察。**

### 5.3 代价，以及为什么可接受

纯滚动（`c3 → d1`）会让 id 变化，于是所有 ref 失效，必须重新 dump。
即：**每次滚动后引用全部作废。**

可接受，理由有三：

1. **正确的 agent 循环本来就要在每次动作后重新观察**——否则无法判断动作
   是否起作用。`screendiff` 的存在就是为了这个。重新 dump 不是额外开销，
   是闭环的必需步骤。
2. 滚动本身就是一个动作，必须验证它滚对了地方。
3. 用「重新 dump 的成本」换「不点错」，在任何 agent 场景都是划算的交易——
   一次点错的代价是整条任务链跑偏，而一次 dump 是几百毫秒。

若确实需要跨滚动跟踪某个元素，那是**另一个需求**，见 §7。

## 6. 深层区分：ref 表达身份，label 表达描述

S3 的 bug 表面上是失效检测缺失，实质是**两种意图被混为一谈**：

| 意图 | 正确工具 | 语义 |
|---|---|---|
| 「我看到的那一行」 | `resolve(ref, since)` | **身份**保持；界面一变即失效 |
| 「当前屏幕上叫 X 的那一行」 | `find_by_label(snap, label)` | **描述**匹配；永远基于最新观察 |

S3 里策略想要的是后者（"Security & privacy 那一行"），却用了前者。
加了双闸门后，这种误用会**立刻报错**而不是静默点错——这比让它"碰巧对"
更有价值。

**规范应明文规定**：`resolve` 与 `find_by_label` 不得互相替代；
`tap_ref` 只能由 `resolve` 产出，不得由 `find_by_label` 的结果冒充。

---

## 7. 不在本提案范围内：稳定元素键

「纯滚动后 ref 全失效」对某些 agent 是真实成本。彻底的解法是给元素一个
**内容派生的稳定键**（如 `resource-id + class + label + 同名序号`），
使同一行在滚动后保持同一个键。

这需要独立解决三个问题：键冲突时的消解规则、键缺失时的退化行为、
以及滚动前后键的匹配算法（与 `screendiff` 的匹配问题高度同源）。

**建议单独立项**，不要塞进本次修订。本提案只做失效检测，把安全性先立住。

---

## 8. 规范条文（拟写入 uidref SPEC §8）

| # | 级 | 条文 |
|---|---|---|
| R1 | 必须 | `resolve(ref, since)` 在 `since` 与当前 `snapshot_id` 不一致时抛 `StaleRefError`，`reason="snapshot_mismatch"` |
| R2 | 必须 | `StaleRefError` 必须携带 `reason`，取值为 `ref_gone` 或 `snapshot_mismatch` |
| R3 | 必须 | `Decision.kind == "tap_ref"` 时 `since` 必填；缺失即为非法决策 |
| R4 | 必须 | 解析失败不得回退到「最近的活元素」或任何静默修正 |
| R5 | 必须 | 实现方不得把 `find_by_label` 的结果当作 `tap_ref` 的 ref 使用 |
| R6 | 应该 | `snapshot_id` 由完整内容派生（哈希），使未变化的界面产生相同 id |
| R7 | 可以 | 提供稳定元素键以支持跨快照跟踪；若提供，须单独规定冲突消解与匹配规则 |

## 9. 验证

见 `tests/test_stale_ref.py`：**18 条**，全部基于 `screendiff/dumps/` 真实 dump。

| 断言 | 判据 |
|---|---|
| 跨页重指派被拒 | `c1` 的 `e5` 解析到 `c2/c3/d1` 上 → `snapshot_mismatch` |
| 跨页是 100% 重指派 | 三组跨页迁移均为 11/11（`test_cross_screen_reassigns_everything`） |
| 同页标签变化被拒 | `c2` 的 `e3` 解析到 `c3` 上 → `snapshot_mismatch` |
| 同快照不误拒 | `since` 与自身 id 相同 → 解析成功 |
| 未变化的界面不误拒 | 两次 parse 同一 XML → id 相同 → 成功 |
| 越界仍报 `ref_gone` | `e999` → `ref_gone` |
| 纯滚动也被拒 | `c3 → d1` 0 重指派，但 id 不同 → 仍拒（**安全性优先**） |
| 两种 reason 可区分 | 调用方能据此决定「重新 dump」还是「重新搜索」 |
| **旧行为会静默放行** | `test_old_behaviour_would_have_succeeded` 证明这是真缺口 |

最后一条是提案存在的理由：它断言"不传 `since` 时同样的输入**不报错**"。
若将来它失败，说明 uidref 已经修好了，提案可以关闭。

## 10. 适用范围

**A 档（可提交）**。理由：

- 问题真实（真机复现 + 4 组真实 dump 量化）
- 修法最小（一个参数 + 一个必填字段），不破坏现有 API 语义
- 有回归测试，且测试用的是真实 dump 而非构造数据
- 命名纪律：全篇不点名任何第三方应用，只谈「元素 / 快照 / 引用」
- 技术无害：纯客户端逻辑，无权限、无网络、无系统调用

**建议与 uidref 主体一并提交**，作为 SPEC §8 与 `resolve()` 的修订。
