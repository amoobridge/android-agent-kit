# 审计总表 · 各库调用了什么、要什么、怎么停

> 面向审阅者：**不需要读代码**，凭本表即可判断每个库碰了什么。
> 每个库另有自己的 `审计表.md`，逐模块更细。
> 本表由各库 `审计表.md` 汇总而来；条数以 `tools/sync_test_counts.py` 实测为准。

## 一、按「碰不碰设备」分三类

### 甲类 · 纯算法库（核心零设备接触）

| 库 | 测试 | 调用了什么 | 要什么权限 |
|---|---|---|---|
| `pointparse/` | 52 | 只解析字符串 | 无 |
| `crosstrack/` | 24 | 只做集合与匹配计算 | 无 |
| `claimaudit/` | 26 | 只读台账 JSON | 无 |

这三个库的核心函数**没有任何 I/O**：输入是字符串或 JSON，输出是字典。
把它们接进任何项目都不引入新的攻击面。

### 乙类 · 核心零设备接触，但附带真机验证工具

| 库 | 测试 | 核心 | 附带工具碰什么 |
|---|---|---|---|
| `uidref/` | 72 | XML → 摘要（纯函数） | `uidref/tools/capture_dumps.py` 调 adb 抓 dump |
| `screenpoint/` | 38 | 坐标反算（纯函数） | `screenpoint/tools/validate_on_device.py` 调 adb |
| `screendiff/` | 33 | 两份快照比对（纯函数） | 测试里起 node 跑 JS 实现 |
| `claimcheck/` | 38 | 声明分级（纯函数） | 无（`claimcheck/core.py` 里 adb 只出现在文档字符串示例） |
| `scrollkey/` | 21 | 键派生（纯函数） | 无 |
| `imespec/` | 37 | 窗口 JSON → 遮挡判定 | `imespec/tools/probe_ime.py` 调 adb |
| `blindspot/` | 37 | 双通道比对 | 测试用 `screencap` 取截图（需 Pillow，缺则 skip） |
| `swipefind/` | 50 | 手势路径几何 | `tools/` 调 adb 做真机取证 |
| `capturetrap/` | 23 | 陷阱判定（纯函数） | 无 |
| `textin/` | 19 | 输入分类与判定 | `textin/tools/compare_paths.py` 调 adb |
| `fieldstate/` | 53 | 状态判定（纯函数） | 无 |

**判据**：把「核心」与「验证工具」分开看。核心可以单独引用而不碰设备；
验证工具只在你想自己复现真机数据时才需要 adb。

### 丙类 · 会写设备

| 库 | 测试 | 写什么 | 撤销 |

| `textin/refapp/` | — （需设备） | 无障碍 `ACTION_SET_TEXT` 向输入框写文本 | 系统设置 → 无障碍 → 关闭服务 |

这是全套件里**唯一会写设备的代码**。详见 `textin/refapp/审计表.md`。

## 二、`uidref/http_api.py` 单独说明

全套件唯一的 HTTP 服务。零依赖（只用标准库）。

| 项 | 状态 |
|---|---|
| 监听地址 | 默认 `127.0.0.1`（只回环） |
| 绑到其他网卡 | 需显式 `--host`，且启动时打印警告 |
| 认证 | **无** |
| TLS | **无** |
| 会写设备的端点 | `/tap`（其余只读） |

**设计前提是「只服务本机」**。跨机使用前必须自己补认证，本套件不代劳。
详见 `uidref/审计表.md`。

## 四、复现方式

```bash
pip install -r requirements.txt    # 仅 pytest
./run-tests.sh                     # 541 条，无需设备、无需网络
```

测试分三段跑：逐库 pytest → JS 黄金向量 → 库级变异扫描。
第三段把每个库的核心算法改坏，验证测试**必须失败**——这是「541 条通过」
这句话有没有意义的判据。
