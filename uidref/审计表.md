# uidref · 审计表

> 本文档说明 uidref 各模块调用了什么、要什么权限、用户在哪一步看到、怎么停。
> 日期：2026-10-27

## 一、适用范围

| 产出 | 说明 |
|---|---|---|
| `uidref/` 库（model + digest） | — | 纯算法、零依赖、可离线验证、不针对任何应用 |
| `SPEC.md` | — | 必须/应该级条文，每条有测试或向量对应 |
| `vectors/` | — | 全部自包含，不引用外部文件，任何语言可跑；条数以 `tools/sync_test_counts.py` 实测为准 |
| `tests/` | — | 含真实 dump 回归与指标断言；无需设备；条数以实测为准 |
| `conformance.py` | — | 可测任意语言实现 |
| `http_api.py` | 附安全说明 | 零依赖标准库；默认 127.0.0.1；见下方审计表 |
| `tools/capture_dumps.py` | — | 采集脚本，绑本机 adb 路径但可参数化 |
| `dumps/` | — | 真实 XML 取证素材，测试从这些文件复算指标 |
| `tools/gen_vectors.py` | — | 生成器，保证向量与实现同步 |

## 二、审计表：用了什么、要什么、用户在哪看到、怎么停

### `uidref` 库（`parse_xml` / `digest` / `resolve`）

| 项 | 内容 |
|---|---|
| 用到的能力 | **无**。纯字符串/XML 解析，不碰设备、不碰网络、不碰文件系统 |
| 需要权限 | 无 |
| 用户同意点 | 不适用 |
| 撤销路径 | 不适用 |
| 拒绝时降级 | 不适用 |
| 数据出境 | 不涉及 |

### `http_api.py`

| 项 | 内容 |
|---|---|
| 用到的能力 | `adb shell uiautomator dump`（读界面结构）；`adb shell input tap`（**会真的点屏幕**） |
| 需要权限 | adb 可达（USB 调试或无线调试）；`uiautomator dump` 无需特殊权限 |
| 用户同意点 | 开启 USB 调试时系统弹窗；`/tap` 被调用时屏幕上有真实可见的点击效果 |
| 撤销路径 | 关掉 adb（拔线 / 关无线调试）即失效；或杀掉进程 |
| 拒绝时降级 | 无 adb 时 `/snapshot` 仍可用（客户端 POST xml），`/tap` 不可用 |
| 数据出境 | 不涉及。界面 XML 只在进程内，不做任何上报 |
| **安全边界** | 默认只绑 `127.0.0.1`；绑 `0.0.0.0` 需显式 `--host` 且启动时打印警告；无认证无 TLS，假设只服务本机客户端 |

### 已知风险与缓解

| 风险 | 缓解 |
|---|---|
| `/tap` 可被本机任意进程调用（无认证） | 绑回环；文档明确「只读用法只调 `/snapshot` 与 `/resolve`」 |
| 绑 `0.0.0.0` 时同网段可控制设备 | 启动时打印显式警告；要求前置网关 |
| snapshot 常驻内存可能含敏感界面文本 | LRU 上限 32 份；无持久化；进程退出即清空 |
| `uiautomator dump` 读到别的应用的界面 | 这是 adb 的既有能力面，uidref 不做额外扩大；`/snapshot` 只读 |

## 追加交付物 · 规范可移植性验证方法（2026-10-27 第二轮）

### 新增文件

| 文件 | 内容 |
|---|---|
| `docs/PORTABILITY.md` | **主交付物**。三层验证法 + 规范歧义分类学（T1–T5 + 覆盖盲区）+ 规范作者自查清单 |
| `tools/verify_impl.py` | **语言无关**一致性验证工具。外部实现方提供「XML 进 JSON 出」的命令即可自测 |
| `js/impl.js` | 契约 CLI 最小包装范例（供外部实现方照抄） |
| `SPEC.md` §10/§11 | 一致性条件 C1–C4、一致性级别 Level 1–3、可移植性证据表 |

### 为什么这是有价值的提交

它不是"又一个 ad-hoc XML 展平器"的说明书，而是**一套可复用的规范验证方法**。
核心论点有实证支撑：**黄金向量全绿不能证明规范可移植**。

uidref 自己的向量曾 34/34 全绿，其中 12 条空转。根因是向量生成器的属性名泄漏
（`cls=` 变成字面 XML 属性，真正的 `class=` 仍是默认值）与自闭合节点
（子孙变兄弟）。期望值用同一份坏输入生成，所以比较仍然相等——
**生成器与实现同源，于是共享盲区，一起错且错得一致。**

打破它的唯一廉价手段是**用第二种语言独立实现规范**：JS 实现写到角色推断时
第一件事是去 XML 里找 `class` 属性，于是立刻发现它不在那儿。

### 顺带发现并修复的覆盖盲区（不属于五类歧义中的任何一类）

§5 的 center 取整规则写了必须，但**比对契约里没有 center 字段**。
后果：拿一个**向零截断**的实现来测一致性，**竟然全绿**——
一致性测试对一个真实分歧完全失明。

修复：center 进契约，并补两条负奇数 bounds 判定用例。
修复后该实现**精确失败 2/45**，正是那两条判定用例——精准，不是大面积误报。

### 量化结果

| 项 | 值 |

### 审计要点

- 全部 Apache-2.0；无第三方依赖（Python 标准库 + Node 标准库）
- 不点名任何第三方应用；以「用户不方便时的场景化辅助」为框架
- `tools/verify_impl.py` 只读文件、只跑子进程，不碰网络、不碰设备
- `docs/PORTABILITY.md` §6 诚实列出方法论的 5 条局限（含"两个实现可能一致地错"）
