# scrollkey · SPEC

**版本** 0.1.0 · **日期** 2026-10-27 · **License** Apache-2.0

**关键词**：必须（MUST）/ 不得（MUST NOT）/ 应该（SHOULD）/ 可以（MAY）。
---

## 1. 范围

定义安卓 UI 元素的**内容派生稳定键**：一种在滚动、翻页后仍然有效的寻址方式。

本规范不定义 XML→元素的投影规则（见 uidref SPEC），
也不定义快照比对的匹配规则（见 screendiff SPEC）。

## 2. 动机：ref 的表达力边界

提案03 量化过：**跨页导航 100% 重指派**。双闸门让这种失效报错而不是静默点错，
但代价是每次滚动后引用全作废。

于是有一个真实需求表达不出来：

> 「我刚才点的那一行」——在滚动之后怎么再找到它？

`ref` 答不了，因为 `ref` 是**序数**，绑定在某一次快照的文档序上。
本规范提供第二种寻址方式：**键**。

| | ref | key |
|---|---|---|
| 语义 | 「**那次**快照里的第 14 行」 | 「**叫 X 的**那一类行」 |
| 绑定 | 快照身份（snapshot_id） | 元素内容 |
| 滚动后 | 失效 | 通常仍有效 |
| 表达 | 身份 | 描述 |

## 3. 键的构造

### 3.1 基键

实现必须按以下优先级取基键：

| 优先级 | 条件 | 基键形式 |
|---|---|---|
| 1 | `resource-id` 非空且非结构性 | `rid:<resource-id>` |
| 2 | `class` 与 `label` 均非空 | `lbl:<class-short>:<label>` |
| 3 | 其他 | `anon:<class-short>` |

`<class-short>` 是 `class` 的最后一段（`android.widget.LinearLayout` → `LinearLayout`）。

**结构性 id 不得作为基键**（`uidref` 的 `is_structural_id`）。
结构性 id 是布局容器名（`content_parent` 之类），对模型无语义，
且多个元素常共用同一个。

### 3.2 冲突消解

基键在同一快照内出现 k 次时，实现必须追加 `#<序号>`，序号 0 起、按文档序：

```
k == 1  →  <基键>
k >= 2  →  <基键>#0, <基键>#1, ...
```

序号不得在其他任何情形下出现（无冲突时不得加 `#0`）。

### 3.3 键到引用的解析

```
resolve_key(snapshot, key) -> Element
```

- 键不存在 → 返回 None（**不得**抛异常，不得回退到"最接近的"）
- 键对应多个元素 → 由 3.2 的序号区分，不应再发生

## 4. 已知边界（诚实清单）

### 4.1 序号只在重复组成员不变时稳定 ★最重要

若滚动导致重复组**新增一行**，组内后续元素的序号整体平移：

```
滚动前   lbl:...:Off#0, lbl:...:Off#1
滚动后   lbl:...:Off#0, lbl:...:Off#1, lbl:...:Off#2   ← 原 #1 仍是 #1，安全
        （在组**前**插入时）lbl:...:Off#0(新), #1(原#0), #2(原#1)  ← 平移
```

即：**键不是无条件稳定的**。它与 ref 有同类问题，只是爆炸半径小得多——
只影响同标签的行，而不是整页。

实现不得声称键"永远稳定"。应当用 §6 的存活率指标量化它。

### 4.2 标签会变

`lbl:` 基键含标签。若元素的标签在两次观察间改变（开关从 Off 变 On），
键就变了——同一行会得到两个不同的键。

**这不是缺陷，是设计选择**：把"标签变了"显式化为"键变了"，
比让键保持不变然后把旧标签当成新标签更安全。

### 4.3 键不能替代重新观察

**键的价值是维持跨帧的指代连续性，不是省掉重新观察。**

要用键点击，仍然需要当前快照来 `resolve_key` → 拿到 ref → 取 bounds。
也就是说：**该 dump 还是要 dump。**

键省掉的是**重新推断"这是哪一行"**，不是**重新观察界面**。
任何把键宣传成"不用重新 dump"的说法都是错的。

### 4.4 匿名元素

`anon:` 基键不含任何内容信息，同一 class 的匿名元素会大量冲突。
此时序号消解会让键退化成"同 class 匿名元素中的第 n 个"——
它比 ref 只多一层 class 过滤，价值有限。

## 5. 实现要求

| 要求 | 级 |
|---|---|
| 结构性 id 不得作为基键 | 必须 |
| 基键优先级按 3.1 | 必须 |
| 冲突时追加 `#<序号>`，无冲突时不加 | 必须 |
| `resolve_key` 找不到时返回 None，不抛异常 | 必须 |
| `resolve_key` 不得回退到"最接近的"元素 | 必须 |
| 提供冲突报告（每快照的重复基键） | 应该 |
| 提供存活率报告（键在序列上的连续出现帧数） | 应该 |
| 键的匹配不得用几何位置（见 screendiff 的教训） | 应该 |

## 6. 量化指标

| 指标 | 定义 |
|---|---|
| `collisions` | 快照内重复基键组数 |
| `key_survival` | 键在滚动序列上连续出现的帧数 |
| `label_drift` | 键的标签在序列上是否变化 |
| `ref_churn` | 同一行在各帧的 ref 变化次数（对照组） |

`ref_churn` 是关键对照：它度量"没有键的话，每次滚动要重新推断多少行"。

## 7. 与 screendiff 的关系

`screendiff` 解决"两份快照怎么比对"，本规范解决"一个元素怎么跨快照指代"。
两者高度同源，但**不得混用**：

- screendiff 的匹配是**几何+身份**的，会跨页误配（其边界清单第 1 条）
- 本规范的键匹配是**纯内容**的，跨页不会误配，但跨页就找不到了

若将来要做跨页跟踪，那需要把两者结合，且必须显式处理"跨页是否允许"。
